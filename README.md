# defi-oracle-vault-python（本地资产库模拟）

一套**本地可运行**的资产库系统：用本地账本（份额）与本地价格源（多源报价）
模拟资产估值与存取，使**价格异常、并发操作与风控熔断**下的资金结论一致、可解释。

- 多来源价格摄入与聚合：缺失 / 过期 / 非正数 / 离群来源被明确拒绝，拒绝原因彼此可区分；
  有效来源不足时资产**明确不可用**，绝不回退到陈旧价或默认价。
- 基于估值的份额存取：份额净值来自聚合价；任意操作序列后份额总量与账本资产严格守恒，
  舍入不会凭空产生或吞掉资产；份额不足 / 资产不可用 / 熔断等失败可区分。
- 风控熔断与受控恢复：窗口内波动超阈、或价格长期不可用即暂停新增敞口；
  恢复必须满足明确条件**且**由有权操作者介入，系统不会静默自愈。
- 测试覆盖并发存取、过期与离群价格、熔断触发与恢复，并在日志中打印价格输入与判定依据。

## 1. 快速开始

```bash
uv sync --group dev          # 安装依赖（含 pytest）
uv run pytest -s             # 运行全部测试（-s 可看到价格/判定日志）
uv run fastapi dev main.py   # 启动 HTTP 服务（默认 http://127.0.0.1:8000）
```

主要 HTTP 接口：

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| POST | `/assets/{symbol}/prices` | 摄入多来源报价，返回聚合判定（接受/拒绝明细） |
| GET  | `/assets/{symbol}/status` | 资产状态：熔断态、最新价、总份额、净现金、触发依据 |
| POST | `/assets/{symbol}/deposit` | 按份额存入 `{user, shares}` |
| POST | `/assets/{symbol}/withdraw` | 按份额提取 `{user, shares}` |
| POST | `/assets/{symbol}/recover` | 授权操作者恢复熔断 `{operator}` |
| GET  | `/healthz` | 健康检查 |

报价请求示例（`price` 用字符串以保留 Decimal 精度，`null` 表示来源缺失）：

```json
{
  "quotes": [
    {"source": "binance",  "price": "100.00", "timestamp": 1000, "observed_at": 1000},
    {"source": "coinbase", "price": "100.05", "timestamp": 1000, "observed_at": 1000},
    {"source": "kraken",   "price": null,     "timestamp": 1000, "observed_at": 1000}
  ]
}
```

所有业务失败返回统一结构：

```json
{"error": {"code": "P005", "message": "..."}}
```

## 2. 多源价格摄入与聚合规则

每个资产配置若干来源（含权重）。每次聚合按顺序校验，任何一步拒绝都记录
**来源 + 原因 + 明细 + 原始价**，彼此可区分：

1. **未配置来源 `unconfigured`**：报价来源不在该资产的来源配置中，直接拒绝。
2. **缺失 `missing`（P002）**：配置来源没有任何报价，或报价为 `null`。
3. **非正数 `non_positive`（P003）**：报价无法解析为有限数字、为 NaN/Inf、或 `<= 0`。
4. **过期 `stale`（P001）**：`当前时间 - timestamp > max_price_age_seconds`；
   时间戳异常地落在未来（超过 1 秒容差）也按过期拒绝。
5. **离群 `outlier`（P004）**：以通过初筛候选的**中位数**为基准，
   相对偏离 `|p - median| / median > outlier_deviation` 即拒绝；
   只有 2 个候选且互相偏离超阈、无法仲裁时，两个都拒绝。
6. 通过校验的来源数 `< min_valid_sources` 时，资产判定为 **不可用（P005）**：
   `usable=false, price=null`，**不会**回退到上一次陈旧价或任何默认价。
7. 有效来源充足时，聚合价为按来源权重的加权平均，并量化到 `price_precision`。

同一来源在一次摄入中给多条报价时，只取 `observed_at` 最新的一条。

> 操作（存/取）时刻还会再次检查"上次有效估值的年龄"，超过 `max_price_age_seconds`
> 一律拒绝（P006），确保不使用陈旧价。

## 3. 份额存取与估值规则

- 账本只登记**份额**；每份价值完全由**操作时刻的聚合价**决定，账本不缓存历史价。
- 现金以 `Decimal` **全精度**记录：`现金 = 份额 × 操作价`，内部不做现金舍入，
  因此精度舍入不可能凭空产生或吞掉资产。
- 份额在存入/提取时按 `share_precision` **向下**量化；量化后为 0 报 L002。
- 对外展示时现金按 `cash_precision` 向下取整，舍下的零头为 `dust`，恒有
  `floor(净现金) + dust == 净现金`（零头可逐笔审计，不丢失、不分配）。

任意操作序列后，以下守恒量严格成立（测试中 `verify_conservation` 逐条断言）：

1. 份额守恒：`Σ各用户份额 == 总份额`，且总份额非负；
2. 现金流逐笔可核对：累计存入/取出现金 = Σ 各笔 `份额 × 操作价`；
3. 盯市恒等式（全精度）：

   ```
   净现金 == 当前总份额 × 当前价 + 历史操作价调整额
   历史操作价调整额 = Σ 带符号份额 × (操作价 - 当前价)   # 存入为正、提取为负
   ```

   它把"按操作时价格记录的现金流"和"按当前价盯市的存量价值"之间因价格变化
   产生的差异，逐笔可解释地归位，没有舍入黑箱。

### 操作判定顺序（失败可区分）

存款：①资产配置(P000) → ②熔断是否开启(**C001**，熔断期暂停新增敞口)
→ ③是否有足够新鲜的有效估值(**P006**) → ④记账（金额非法 **L002**）。

提款：①资产配置(P000) → ②有效估值(**P006**) → ③份额是否足够(**L001**)。

熔断期间**允许提取**（允许退出敞口），但**禁止新增存款**。

## 4. 风控熔断与受控恢复

### 触发条件（任一满足即 OPEN，记录不可变触发依据）

- **波动超限 `volatility`**：观察窗口 `observation_window_seconds` 内，
  被接受聚合价的 `(max - min) / min > volatility_threshold`。
- **长期不可用 `prolonged_unavailable`**：价格连续不可用的持续时长
  `> unavailable_grace_seconds`（从首次不可用观察算起；一旦出现有效估值即清零）。

OPEN 期间：拒绝该资产新增存款（C001，返回全部触发依据），允许提取。

### 恢复条件（必须全部满足，且由有权操作者显式调用）

- 当前处于 OPEN；未触发时调用恢复返回 **C002**；
- 熔断后已累计 `>= recovery_required_valid_observations` 次**连续**有效估值；
- 这些估值位于观察窗口内，且窗口内波动不超过 `volatility_threshold`；
- 操作者在 `recovery_operators` 白名单内，否则 **C004**（越权）；
- 条件不满足返回 **C003**（携带逐条未满足原因）。

系统**不会静默自动恢复**；熔断瞬间会清空触发前的价格历史，恢复只考察
熔断之后的稳定观察，避免"造成熔断的旧点"永久阻塞恢复。

## 5. 失败语义（错误码总表）

| code | 含义 | 典型 HTTP |
| ---- | ---- | --------- |
| P000 | 资产未配置 | 404 |
| P001 | 来源报价过期（含未来时间戳） | 422 |
| P002 | 来源缺失报价 | 422 |
| P003 | 报价非正数/不可解析 | 422 |
| P004 | 报价离群 | 422 |
| P005 | 有效来源不足，资产不可用（不回退） | 409 |
| P006 | 操作时刻无足够新鲜的有效估值 | 409 |
| L001 | 份额不足 | 400 |
| L002 | 金额/份额非法（非正、NaN、量化为 0、无法解析） | 400 |
| C001 | 熔断生效，拒绝新增存款 | 409 |
| C002 | 熔断未触发，无需恢复 | 409 |
| C003 | 恢复条件不满足（返回未满足项） | 409 |
| C004 | 恢复操作者越权 | 403 |

## 6. 配置项

每个资产由 `AssetConfig` 配置（见 `app/models.py`，演示值见 `app/demo.py`）：

| 配置项 | 含义 | 默认 |
| ------ | ---- | ---- |
| `sources` | 来源列表（名称 + 权重 `weight`） | — |
| `min_valid_sources` | 聚合所需最少有效来源数 | 2 |
| `max_price_age_seconds` | 报价最大年龄（秒），超过判过期；也是操作时估值保鲜年龄 | 60 |
| `outlier_deviation` | 离群阈值（相对中位数偏离比例，0.05=5%） | 0.05 |
| `volatility_threshold` | 观察窗口允许的最大相对波动 | 0.10 |
| `observation_window_seconds` | 波动/恢复观察窗口（秒） | 300 |
| `unavailable_grace_seconds` | 价格持续不可用多久触发熔断（秒） | 120 |
| `recovery_required_valid_observations` | 恢复所需连续有效估值次数 | 3 |
| `price_precision` | 聚合价量化网格 | 1e-8 |
| `share_precision` | 份额量化网格 | 1e-8 |
| `cash_precision` | 现金展示网格（内部仍全精度） | 1e-8 |

全局 `VaultConfig.recovery_operators` 为有权恢复熔断的操作者白名单（默认 `risk_admin`）。

## 7. 代码结构与测试

```
app/
  errors.py    # 全部失败类型与稳定错误码
  models.py    # 配置、报价、聚合结果、熔断/账本记录等数据模型
  price.py     # 多源摄入、四类拒绝、加权聚合、可用性判定
  risk.py      # 波动/长期不可用熔断、受控恢复
  ledger.py    # 份额账本：全精度现金、守恒校验、线程锁
  vault.py     # 门面：判定顺序 + 每资产锁，保证"判定+记账"原子
  service.py   # FastAPI：路由与统一错误码响应
  demo.py      # 本地演示装配（BTC/ETH 示例配置）
tests/
  test_price.py                  # 缺失/过期/非正/离群/来源不足
  test_risk.py                   # 波动触发、长期不可用、越权/条件/恢复
  test_ledger.py                 # 守恒、舍入零头、份额不足、并发存取
  test_vault.py                  # 全链路失败可区分、熔断阻断存款/允许提取
  test_service.py                # HTTP 状态码与错误码
  test_concurrency_integration.py# 并发存取 × 并发喂价（含异常价/熔断）压力
```

并发安全：账本有一把可重入锁；门面为每个资产再持一把锁，
"熔断判定 → 估值新鲜度 → 记账"在同一临界区内原子完成，跨资产互不阻塞。
